| DOC-021 | **uDSC 16-bit access = register-PAIR transfer, not adjacent IO slots** (silicon-verified 2026-09-04). One `out <reg>, r_lo` with a 16-bit value in a register pair moves the whole pair (vendor `dsu_xmuluu` + ibawizard LGT8F328P notes: "loads r22:r23 to DY with one `out DSDY, r22`"). AND: uDSC samples the HIGH register of the pair first — a pipeline hazard if the compiler's last load (high byte) has not propagated. | `setX/setY/setAccumulator` = single pair-`out` with a `nop` between operand load and `out`; reads = single pair-`in` ("=w"). | DOC-022 | **DSSD register (IO 0x02, "16-bit saturation result") does not function on silicon** — reads constant 0xFF/0xFFFF across every operation in every probe dump; it is not a usable saturation result. | DSP16 operators now read the proven 32-bit accumulator (DSAL/DSAH pairs) and clamp in software via `sat16()`; `dsp::saturated()` kept for API compatibility but unused internally. | **PASS on silicon 2026-09-04**: DSP16 30000*2 saturates to 32767 (LQFP48). |
| DOC-023 | **WDT interrupt mode does not work on tested silicon (LGT8F328P-LQFP48)**. Probe evidence (7 probes, 2026-09-04): WDTCSR reads back 0x40 (WDIE=1, WDE clean) after windowed arm; ISR properly installed on `__vector_6`; ISR with in-window disarm, re-arm, and plain variants all tried — the timeout ALWAYS resets the chip and the ISR NEVER fires (LED/noinit evidence). Databook mode-table row "WDE=0/WDIE=1 = Interrupt" does not match this die. Reset mode (WDE=1 + WDR feeding) works. | WDT.h: `.init0` trampoline removed; `wdt_ienable()` kept for API compat but documented as behaving like reset-mode arm on this silicon. silicon_verify WDT test = reset-mode arm + 300ms feeding (no reset) + disarm. Use WDT in RESET mode only. | RESET-mode arm/feed/disarm verified working on silicon; interrupt mode conclusively non-functional on this die (may differ on other LGT8F328P packages/revisions - HW-test before relying on it). |
| DOC-024 | **Native 32-bit EEPROM program mode is broken on LQFP48** (probe-verified 2026-09-04): write32(0,0xA5A5A5A5) left flash = A5 00 00 00 (only byte0 staged via E2PD0 lands); write32(64,0xDEADBEEF) left bytes 1-3 unwritten. E2PD0..3 addresses match dbuezas upstream, so this is a die behavior, not a header bug. Byte-mode writes (EECR 0x00 + EEDR) are silicon-proven for single AND multi-byte writes incl. across page swaps; 32-bit READ mode works. | `lgt_eeprom_write32` and `lgt_eeprom_writeSWM` now use the byte-mode engine (4x write_byte, logical addressing so hole-skip applies per byte). Smoke SWM test corrected (was invalid for the 1KB partition). | Byte-mode multi-write + 32-bit read verified on silicon; native 32-bit write conclusively broken on this die. |
| DOC-025 | **Two uDSC arithmetic quirks on LQFP48** (byte-accurate suite + sub-probe, 2026-09-04): (1) DIVMOD is a SIGNED 32-bit division - unsigned dividend 0xFFFFFFFF gives q=0 r=1 (= abs(INT32_MIN-1)/1000 path) instead of q=4294967 r=295; 0x80000000 only passed by coincidence (abs(INT32_MIN) == its unsigned value).
